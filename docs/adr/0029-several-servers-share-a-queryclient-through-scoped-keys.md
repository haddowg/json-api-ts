# Several servers share a QueryClient through scoped keys

An app talking to two servers (a public API and its admin API, say) wants one QueryClient, but the `type:id` normalisation can't tell two servers' `users` apart, so it previously required one descriptor per QueryClient. A scope leads each server's query and mutation keys with an object segment, `{ $scope }`, which no type name can collide with, and each descriptor normalises, patches and invalidates only the keys in its own scope, so one descriptor per scope replaces one per QueryClient while unscoped keys stay exactly as they were. Prefixing keys was chosen over tagging cached data with its server because TanStack's prefix matching then keeps every filter, invalidation and `isMutating` call inside its scope without any help from the binding.

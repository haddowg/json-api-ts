# The client guards structure only, validation is opt-in, and runtime dependencies stay shallow

The same document generates the server's output and this client, and the envelope is invariant, so the runtime runs only light structural guards (a JSON:API document whose `data` carries `type` and `id`) and otherwise trusts the wire. Full per-resource validation against the server's JSON Schemas is an opt-in `validate` seam whose engine, such as ajv, the app brings, and a missing include leaves an identifier rather than throwing. For the same reasons the runtime isn't strictly zero-dependency: a dependency is acceptable when it is tiny or well maintained and has a shallow tree, because the goal is limiting supply-chain exposure and bundle size, while build tooling is judged on stability instead.
